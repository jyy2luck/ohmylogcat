## Why

终端界面启动后看不到当前包版本，也无法知道 GitHub 是否已发布更新。用户只能退出后执行 `--version` 或 `update`。在底部栏常驻版本号、有更新时追加提示，能在不停拉流的情况下给出信号。

## What Changes

- 底部栏最右侧常驻当前包版本（简体示例：`版本-0.6.0`）。
- 后台对照 GitHub 最新发行标签；仅当远端版本更大时，在版本号后追加括号（简体示例：`版本-0.6.0（有更新0.7.0）`）。
- 探测失败、离线、或尚无结果时，只显示当前版本，不把网络失败画成错误。
- 错误、复制、导出等短提示改到版本簇左侧的中间槽；版本簇钉在最右，不让路。
- 不在界面内执行更新；不改命令行 `update` / `--version` 行为。
- 探测不得走未认证的 GitHub 发布接口（REST API），沿用现有 `releases/latest` 跳转解析。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `log-buffer`：底部栏增加最右侧版本簇；错误与短暂提示改为占用条数与版本之间的中间区域。
- `tui-shell`：终端界面启动后非阻塞探测最新发行版，按语义化版本比较决定是否显示更新后缀。

## Impact

- `src/app.rs`：`draw_status` 三区布局；启动时发起探测并在事件循环中收取结果。
- `src/cli.rs`（或抽出的共享模块）：复用 `releases/latest` 跳转解析；版本比较改为「远端更大」而非字符串相等（界面提示用；命令行比较策略可保持现状）。
- `src/ui/i18n.rs`：英 / 简 / 繁版本与「有更新」文案。
- `src/main.rs`：若需在应用循环中轮询探测结果，改动应尽量小。
- 不新增 HTTP 依赖；继续用系统 `curl` / PowerShell。
- 单元测试：版本文案拼接、语义化比较、窄宽度时优先丢掉更新括号。
